# Чек-лист и тест-кейсы

Документ предназначен для ручной проверки демо и воспроизводимой проверки API. Входы и ожидаемые результаты сверены с каталогом команды. Сценарий площадки специально проверяет многокатегорийный профиль и метки происхождения данных.

## Перед началом

- [ ] Запущен backend из recommendation-logic.
- [ ] GET /health возвращает status=ok и profiles_loaded=66.
- [ ] GET /filters возвращает города, категории, форматы, языки и окно календаря 2026-09-23—2026-12-31.
- [ ] Демо выполняется без параметра ?demo=1, если проверяется настоящий подбор.
- [ ] Для базовой проверки ИИ выключен; API-ключ не требуется.
- [ ] Подготовлены тестовые запросы из таблицы ниже.

## Основные сквозные кейсы

| ID | Запрос / действие | Ожидаемый результат |
|---|---|---|
| TC-01 | Алматы · 2026-10-07 · свадьба · Ведущий · бюджет 1 000 000 ₸ · язык казахский | HTTP 200, outcome=matches, eligible=4, максимум 3 карточки. Порядок: HK-35215 (Кики), HK-42352 (Эмилия), HK-27222 (Сон Гоку). В сообщении указано «Подобрано 3 из 4»; Хаул остаётся четвёртым подходящим. |
| TC-02 | Повторить TC-01 без изменения параметров | Те же ID и тот же порядок карточек. |
| TC-03 | В TC-01 изменить только дату на 2026-10-03 | HTTP 200, outcome=no_match, карточек нет. Сообщение объясняет, что четыре иначе подходящих профиля заняты на эту дату. |
| TC-04 | Алматы · 2026-10-04 · свадьба · Флорист · бюджет 250 000 ₸ · язык русский | HTTP 200, outcome=matches, eligible=2. ID: HK-39372 и HK-90001. Не добавлять профиль из Астаны. У HK-39372 price_imputed=true; у HK-90001 synthetic=true. |
| TC-05 | В TC-04 изменить только бюджет на 100 000 ₸ | HTTP 200, outcome=no_match, карточек нет. Объяснение: два профиля проходят остальные условия, но их цена «от» выше бюджета; минимальная подходящая стартовая цена — 200 000 ₸. |
| TC-06 | Зарубежье · 2026-10-04 · свадьба · Флорист · бюджет 250 000 ₸ | HTTP 200, outcome=category_absent, карточек нет. Отдельно сказано, что в выбранном городе нет этой категории. |
| TC-07 | Алматы · 2026-10-08 · свадьба · Банкетный зал · бюджет 3 500 000 ₸ | HTTP 200, outcome=matches, eligible=4, показаны HK-50695, HK-64395, HK-58236 именно в таком порядке. В каждой карточке один подрядчик; отображены все его категории. У трёх показанных профилей city_imputed=true, price_imputed=true, synthetic=false. |

## Проверки фильтров и карточек

- [ ] Город и категория работают совместно: профиль из другого города не попадает в карточки.
- [ ] Занятый подрядчик исключён даже при совпадении бюджета, формата и языка.
- [ ] Цена проверяется как верхний предел бюджета; цена, равная бюджету, проходит.
- [ ] Неподдерживаемый формат при существующей категории приводит к no_match с причиной, а не к category_absent.
- [ ] Язык ограничивает выдачу только если пользователь его указал. Например, в TC-04 запрос с языком казахский оставляет HK-90001.
- [ ] Длительность ограничивает выдачу только если пользователь её указал. Если max_hours меньше запроса, профиль исключён.
- [ ] max_hours=null не исключает профиль при заданной длительности; карточка уточняет, что работа не привязана к часам присутствия и сроки нужно согласовать.
- [ ] Для многокатегорийного профиля поиск по одной категории не создаёт дубли. В карточке показан полный список категорий.
- [ ] Цена на карточке обозначена как «от». Если price_imputed=true, отображается метка ориентировочной цены.
- [ ] city_imputed=true отображается отдельно от synthetic=true; одна метка не подменяет другую.
- [ ] Каждая карточка содержит индивидуальное объяснение из фактов профиля и параметров запроса. Нет взаимозаменяемых общих фраз.
- [ ] Пустая выдача содержит понятное сообщение и остаётся штатным ответом API, не пустым экраном и не HTTP 500.
- [ ] Порядок — цена «от» по возрастанию, затем ID; не называем его оценкой качества.

## Проверки ввода и границ

| ID | Вход | Ожидаемый результат |
|---|---|---|
| TC-08 | Дата 2026-09-23 и дата 2026-12-31 | Обе границы календаря принимаются. |
| TC-09 | Дата 2026-09-22 или 2027-01-01 | HTTP 422: дата за пределами календаря, доступность неизвестна. |
| TC-10 | Несуществующая дата, например 2026-02-30 | HTTP 422 с ошибкой даты. |
| TC-11 | Бюджет 0, отрицательное значение, дробь, строка или boolean | HTTP 422; сервер не падает и не принимает строку как число. |
| TC-12 | Неизвестное поле в JSON, например languag | HTTP 422, ошибка привязана к полю; параметр не игнорируется молча. |
| TC-13 | Пустой язык или строка из пробелов | HTTP 422. Чтобы не фильтровать по языку, поле нужно пропустить или передать null. |
| TC-14 | Неизвестный город или категория | HTTP 200, outcome=category_absent, понятное сообщение. |
| TC-15 | Неизвестный язык при существующих профилях категории в городе | HTTP 200, outcome=no_match с объяснением языкового ограничения. |

## Проверка интерфейса

- [ ] Форма предлагает значения из GET /filters и даты только в доступном окне.
- [ ] При подборе виден статус загрузки; после ответа отображается message.
- [ ] Для результата показаны до трёх карточек, полные категории, город, цена «от», объяснение и метки происхождения.
- [ ] Для category_absent и no_match видны разные заголовки и текст причины.
- [ ] На языке интерфейса, отличном от русского, пользователь видит пометку, что объяснение сервиса дано на русском.
- [ ] Кнопка «Связаться» не изображается как реальное бронирование: демонстрационная версия ничего не бронирует и не отправляет заявку.

## Проверки времени и повторяемости

- [ ] Типовой запрос укладывается в ориентир до 10 секунд.
- [ ] Повтор одного запроса сохраняет ID и порядок карточек.
- [ ] При изменении даты на занятый день результат и текст причины меняются.
- [ ] Ручной просмотр подтверждает, что цитаты полные и действительно взяты из описания, а объяснения различают подрядчиков без имён.

## Команды для воспроизводимой проверки

Из recommendation-logic:

```powershell
python -m unittest discover -s tests -v
node --test qa/frontend-integration.test.mjs
python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

В другом терминале, также из recommendation-logic:

```powershell
python qa/demo_check.py --base-url http://127.0.0.1:8000
```

Интеграционный скрипт использует JSON-кейсы из examples/demo-cases.json. Он проверяет исход, ID/порядок, число подходящих профилей, сообщение, наличие датированного объяснения и булевы поля происхождения. TC-07 дополнительно проверяет полный список категорий и конкретные значения флагов.

Перед защитой запишите результат каждой проверки: PASS / FAIL, фактическое сообщение и скриншот только для UI-кейсов. Не отмечайте непроверенный сценарий как PASS.
