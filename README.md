## О проекте

«Повод» помогает организаторам свадеб, корпоративов и других мероприятий в Казахстане выбрать специалистов и площадки из каталога. Сервис учитывает условия события, исключает неподходящие варианты и объясняет рекомендации фактами из профилей.

> Главное — не просто показать карточки, а объяснить, почему они подходят. Если вариантов мало или нет, пользователь узнает причину.

Проект решает кейс **«Умный подбор подрядчиков (#79-lite)»**. Основной сценарий работает локально: без API-ключей, платных вызовов и базы данных.

## Что реализовано

- **Подбор до трёх вариантов.** Город, дата, категория, формат и бюджет; язык и длительность — по желанию.
- **Индивидуальные объяснения.** Особенность из профиля, соответствие запросу, стартовая цена и доступность на дату.
- **Честная выдача.** Занятые и неподходящие профили исключаются; редкие категории и пустые результаты объясняются словами.
- **Описание события своими словами.** «Опишу своё событие» разбирает русский текст по правилам, уточняет поля и предлагает подтвердить их перед подбором.
- **Каталог и справочник.** Поиск по имени или ID, фильтры, подробности профилей и локальная помощь по работе сайта.

Интерфейс поддерживает светлую и тёмную темы, RU / KK / EN и сохранение черновика формы. Описания профилей, объяснения и ответы помощника остаются на русском.

## Как работает решение

1. **Опишите событие:** заполните форму или воспользуйтесь текстовым помощником и подтвердите распознанные поля.
2. **Получите подбор:** сервис проверит каталог и вернёт до трёх подходящих карточек.
3. **Сравните объяснения:** прочитайте особенности профилей, условия и цену «от». При пустом результате измените условия по подсказке.

```text
Параметры события
      ↓
Проверка ввода → город и категория → занятость и остальные условия
      ↓
Сортировка по стартовой цене, затем по ID
      ↓
До трёх карточек с объяснениями — или понятная причина отсутствия вариантов
```

Одинаковые параметры дают одинаковый порядок. Это **сортировка по цене, а не рейтинг качества**.

В объяснении сначала выделяется конкретный факт из профиля, затем показывается его соответствие заказу. Цитаты берутся из описаний, цены и занятость — из структурированных данных. Если отличительных сведений мало, сервис не выдумывает преимущества.

Подробные правила и обработка пограничных случаев — в [описании пайплайна](docs/pipeline.md).

## Технологии

| Часть | Стек |
|---|---|
| Backend | Python · FastAPI · Pydantic · Uvicorn · HTTPX |
| Frontend | HTML · CSS · JavaScript ES modules — без React и сборщика |
| Данные | Локальный CSV и проверяемый снимок каталога для интерфейса |
| Проверки | Python unittest · Node.js test runner · демо- и нагрузочные сценарии |
| Шрифты | Lora · Golos Text · Manrope — локальные файлы с лицензиями OFL |

**Роль ИИ.** Основной подбор и текстовый помощник работают по правилам. Опциональный модуль OpenAI Responses API может выбрать исходную фразу для объяснения уже отобранной карточки, но не меняет кандидатов, порядок, цены или календарь. Произвольный текст модели не выводится; при ошибках используется обычное объяснение.

Интеграция выключена в обычном сценарии. Настройки, модель и условия включения — в разделе [«Данные и интеграции»](#данные-и-интеграции).

## Архитектура

Один процесс FastAPI обслуживает сайт и API. Браузер передаёт параметры движку подбора, который работает с локальным каталогом. Текстовый помощник заполняет параметры для того же движка.

```text
frontend/                   Форма, карточки, каталог, темы и справочник
contractor_assistant/       Разбор описаний событий и уточнение параметров
recommendation-logic/       API, движок подбора, данные, тесты и QA
docs/                       Демо-сценарии, пайплайн и отчёт приёмки
```

Основные маршруты: `/recommendations` — подбор, `/assistant/chat` — помощник, `/filters` — значения формы, `/health` — состояние сервера. Интерактивный контракт доступен по `/docs` после запуска.

Ответ подбора содержит карточки, объяснение результата и статистику. Три штатных исхода — `matches`, `category_absent`, `no_match` — возвращаются с HTTP 200; некорректные параметры отклоняются валидацией.

Полный контракт, примеры JSON и коды ошибок: [Backend README](recommendation-logic/README.md) · [Интеграция frontend/backend](recommendation-logic/HANDOFF.md).

## Быстрый старт

Нужны **Git и Python 3.10+**. Проверено на Windows с Python 3.13.12. Node.js 22+ понадобится только для JavaScript-тестов; npm и сборка frontend не нужны.

### 1. Скачайте репозиторий

Для приватного репозитория нужен доступ команды. Если он уже скачан, откройте его корневую папку и переходите к шагу 2.

```bash
git clone https://github.com/BAITC-Hacks/hack-22efa0ed-codexflow.git
cd hack-22efa0ed-codexflow
```

### 2. Запустите сервер

**Windows · PowerShell**

```powershell
cd recommendation-logic
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

<details>
<summary>Команды для macOS и Linux</summary>

Из корня репозитория:

```bash
cd recommendation-logic
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

</details>

### 3. Откройте сайт

**[Открыть «Повод» →](http://127.0.0.1:8000/ui/)**

[Swagger API](http://127.0.0.1:8000/docs) · [Состояние сервера](http://127.0.0.1:8000/health) — ожидается `profiles_loaded: 66`.

Не открывайте `frontend/index.html` двойным щелчком: сайту нужен работающий сервер. Остановка — `Ctrl+C`. Если порт занят, замените `8000`, например, на `8013` в команде запуска и адресе браузера.

## Как проверить

### Короткий маршрут для жюри

Откройте сайт **без `?demo=1`**. В форме доступны быстрые примеры «Ведущий», «Флорист» и «Низкий бюджет». Выберите условия и нажмите «Подобрать подрядчиков».

Для трёх запросов ниже: **Алматы · свадьба · длительность не задана**.

| Сценарий | Параметры | Что показать |
|---|---|---|
| Плотная категория | 07.10.2026 · Ведущий · 1 000 000 ₸ · казахский | Кики, Эмилия, Сон Гоку: три карточки из четырёх подходящих |
| Редкая категория | 04.10.2026 · Флорист · 250 000 ₸ · русский | Тони Тони Чоппер и Тихиро Огино: две карточки с разными объяснениями |
| Пустой результат | 04.10.2026 · Флорист · 100 000 ₸ · русский | Нет карточек: стартовые цены свободных кандидатов выше бюджета |

**Две контрольные проверки:** повторите первый запрос — порядок должен сохраниться. Затем измените только его дату на **03.10.2026** — выдача станет пустой, а объяснение укажет занятость четырёх иначе подходящих профилей.

У флористов сравните факты в объяснениях: объём выполненных заказов у одного и работу с цветовой палитрой у другого. Метки синтетических профилей и ориентировочных данных должны быть видны.

- **Нет категории в городе:** Зарубежье · 04.10.2026 · свадьба · Флорист · 250 000 ₸ → `category_absent` с пояснением.

## Данные и интеграции

Источник — [`providers.csv`](recommendation-logic/data/providers.csv): **66 анонимизированных профилей**, из них **13 синтетических**. География — Алматы, Астана и «Зарубежье». Календарь — **23.09.2026–31.12.2026**, 100 дней.

В каталоге 15 ведущих, 12 фотографов и 8 банкетных залов; в ряде редких категорий — по 3 профиля. Категории могут пересекаться: один подрядчик не превращается в несколько карточек.

Цена «от» — стартовая стоимость мероприятия, не окончательная смета. Синтетические профили, дополненный город и дополненная цена отмечаются независимо. Свободная дата в датасете не подтверждает бронирование.

Каталог интерфейса хранится в `frontend/catalog-data.js`; тест сверяет его поля с серверным CSV. При изменении данных нужно обновлять оба представления.

<details>
<summary>Опциональная интеграция OpenAI</summary>

Используется OpenAI Responses API; модель по умолчанию — `gpt-4o-mini`, настройка — `OPENAI_MODEL`. Для включения нужны серверные настройки, ключ и явный параметр API `ai_explanations=true`. Само наличие ключа не включает ИИ в обычной форме.

Реальные платные вызовы в итоговом QA не проверялись: модельный транспорт тестировался с заглушкой. NVIDIA API в текущий код не интегрирован.

Ключи хранятся только на сервере. `.env` исключён из Git, но обычный запуск не загружает его автоматически. [Настройка и ограничения ИИ →](recommendation-logic/AI.md)

</details>

Для основного сценария внешние API и отдельная БД не нужны; каталог и шрифты загружаются локально.

## Ограничения

- **Учебный каталог.** Анонимизированные данные и заявления профилей не являются проверенной информацией о реальных услугах. Даты вне указанного календаря не принимаются.
- **Рекомендация, не заказ.** Нет бронирования, оплаты, отправки заявок или уведомлений. «Связаться» показывает пояснение.
- **Помощник по правилам.** Он не гарантирует понимание произвольной речи; распознанные поля нужно подтвердить. Ручная форма всегда доступна.
- **Демо, не готовый публичный сервис.** Есть валидация и ограничения запросов, но перед размещением нужны HTTPS, ограничение частоты запросов, защита платного ИИ и проверка зависимостей. См. [SECURITY.md](recommendation-logic/SECURITY.md).
- **Границы проверки.** Живой LLM, публичный хостинг и чистая установка на другой ОС не подтверждены тестированием. Зависимости заданы диапазонами, полного lock-файла нет.

## Развёрнутая версия

Подтверждённой публичной версии пока нет. Для проверки используйте [локальный сайт](http://127.0.0.1:8000/ui/) после [запуска сервера](#быстрый-старт).

`127.0.0.1` доступен только на компьютере с запущенным сервером. Push в GitHub сохраняет исходный код, но не размещает сайт в интернете.
