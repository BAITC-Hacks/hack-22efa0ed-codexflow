# Повод — умный подбор подрядчиков

**До трёх специалистов для вашего события — с объяснением каждого выбора.**

Рабочий прототип для HackAlem AI: интерфейс, API, каталог и воспроизводимые проверки в одном репозитории. Основной сценарий запускается локально без API-ключей.

[Запуск](#7-установка-и-запуск) · [Проверка для жюри](#8-как-проверить-решение) · [Данные](#9-данные-и-интеграции) · [Ограничения](#10-ограничения) · [Документы](#дополнительная-документация)

## 1. Название проекта

**Повод — умный подбор подрядчиков.** Команда — **CodexFlow**. Хакатон — **HackAlem AI**, трек — **«Креативные индустрии»**, кейс — **«Умный подбор подрядчиков (#79-lite)»**.

## 2. Краткое описание

Сервис предназначен для организаторов свадеб, корпоративов и других мероприятий в Казахстане. Он решает проблему выбора из каталога: вместо длинного списка возвращает до трёх подрядчиков, соответствующих городу, дате, формату и бюджету, и объясняет каждую рекомендацию проверяемыми фактами из профиля.

Главная ценность — не сортировка сама по себе, а понятные причины выбора и честное объяснение, когда подходящих вариантов мало или нет.

## 3. Что реализовано

- **Подбирать специалистов и площадки.** Проверяет город, категорию, занятость, формат и бюджет; по желанию — язык и длительность.
- **Объяснять каждый вариант.** В карточке — конкретная особенность из профиля и её соответствие условиям заказа. Цена всегда указана как «от».
- **Честно показывать ограниченную выдачу.** Если вариантов два, один или нет, сервис объясняет причину и не добавляет неподходящих людей ради количества.
- **Сохранять порядок.** Для одинаковых параметров карточки идут в одном порядке: по стартовой цене, затем по ID. Это не рейтинг качества.
- **Принимать описание события.** «Опишу своё событие» предлагает шаблоны, разбирает русскоязычный текст по правилам, уточняет недостающее и просит подтвердить параметры перед подбором.
- **Давать просматривать каталог.** Поиск по имени или ID, фильтры города и категории, подробности профилей и метки происхождения данных.
- **Помогать освоиться.** «Справочник» справа снизу объясняет работу сайта; это локальная инструкция, не ИИ-чат.

В интерфейсе есть светлая и тёмная темы, переключение RU / KK / EN и сохранение черновика основной формы на устройстве. Объяснения, исходные описания и ответы помощника остаются на русском; перевод интерфейса не меняет данные запроса.

**Бронирование, оплата, отправка заявок и уведомления подрядчикам не реализованы и не входят в задачу.** Кнопка «Связаться» показывает пояснение, а не отправляет заявку.

## 4. Как работает решение

1. Откройте сайт и укажите город, дату, формат события, категорию подрядчика и бюджет. Язык и длительность необязательны.
2. Либо нажмите **«Опишу своё событие»**, выберите шаблон или опишите заказ на русском. Помощник уточнит недостающие поля; проверьте их и подтвердите подбор.
3. Сервис проверит каталог, исключит занятых и неподходящих специалистов и вернёт до трёх карточек.
4. Сравните цену «от» и объяснения. При малом числе вариантов или пустом результате прочитайте причину, измените условия и повторите подбор.
5. Заявки и оплата не отправляются: результат — рекомендация, а не бронь.

### Правила принятия решения

```text
Форма или подтверждённое описание события
                    ↓
Проверка типов, границ и нормализация параметров
                    ↓
Город + категория ── нет профилей → category_absent
                    ↓
Дата + бюджет + формат + язык + длительность
                    ├── никто не прошёл → no_match с причинами
                    ↓
Цена «от» по возрастанию → ID → до трёх карточек
                    ↓
Факт из профиля + соответствие запросу + метки данных
```

Первое предложение объяснения выделяет конкретную особенность профиля: опыт, языки, репертуар, состав музыкантов, оформление или условия площадки. Второе связывает карточку с параметрами заказа. Цитаты берутся из описаний, а цены и доступность — из структурированных полей.

Если отличительных сведений недостаточно, сервис сообщает об этом, а не выдумывает преимущества. Подрядчик с несколькими категориями остаётся одной карточкой. `max_hours = null` означает, что услуга не привязана к часам присутствия, а не обещание неограниченной работы.

Причины отказа могут пересекаться: один профиль бывает одновременно занят и дороже бюджета. Поэтому сумма `stats.rejected` не равна числу исключённых людей.

## 5. Технологии

**Backend:** Python, FastAPI, Pydantic, Uvicorn; HTTPX для опционального модельного транспорта и тестов. **Frontend:** HTML, CSS, JavaScript ES modules, без React и сборщика. Шрифты Lora, Golos Text и Manrope хранятся локально вместе с лицензиями OFL; подключение к Google Fonts при работе сайта не требуется.

### AI-модели и роль ИИ

Основной подбор и помощник описания работают **по правилам, без обязательного LLM**. Сайт по умолчанию не делает платных вызовов.

Опциональный модуль может попросить модель выбрать индекс подходящей исходной фразы для уже отобранных карточек. Он не меняет кандидатов, порядок, цены или календарь. Сервер проверяет выбор; при ошибке, таймауте или одинаковых объяснениях возвращает обычные объяснения по правилам. Произвольный текст модели не попадает в карточки.

Для этого нужны серверные настройки и явный параметр `ai_explanations=true` в API-запросе. Само наличие ключа не включает ИИ в обычной форме. Инструкция — [AI.md](recommendation-logic/AI.md). Реальные платные вызовы в итоговом QA не проверялись; модельный транспорт тестировался с заглушкой.

## 6. Архитектура проекта

Основные компоненты: браузерный интерфейс → FastAPI → движок подбора и локальный каталог. Помощник преобразует описание в параметры того же движка, а опциональный модельный модуль работает только с объяснениями уже выбранных карточек.

```text
frontend/                       Интерфейс, каталог, темы и локализация
  app.js, api.js                 Управление формой и связь с API
  cards.js                      Карточки и объяснения
  assistant-preview.js          Рабочий помощник описания события
  guide.js                      Локальный справочник
  assets/fonts/                 Шрифты и лицензии
contractor_assistant/
  chat.py                       Разбор русскоязычных описаний по правилам
  test_chat.py                  Отдельные тесты помощника
recommendation-logic/
  src/recommendation.py          Фильтрация, порядок и объяснения
  src/api.py                    HTTP-контракты и раздача сайта
  src/http_safety.py             Ограничения и защита входящих запросов
  src/ai_explanations.py         Опциональный выбор фактов моделью
  data/providers.csv            Исходный каталог
  tests/                        Модульные и интеграционные проверки
  qa/                           Демо, нагрузка и frontend-тесты
  examples/demo-cases.json       Контрольные запросы и ожидания
docs/                           Сценарии, пайплайн и отчёт приёмки
```

Старые файлы плавающего чата `frontend/assistant-ui.js` и `contractor_assistant/widget.*` сохранены, но основной интерфейс их не монтирует. Рабочий путь описания события — `assistant-preview.js` → `/assistant/chat` → подтверждение → `/recommendations`.

### HTTP-контракт

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Состояние и число загруженных профилей |
| `GET /filters` | Значения для формы и окно календаря |
| `POST /recommendations` | Основной подбор |
| `POST /assistant/chat` | Разбор описания события и уточнение параметров |
| `GET /docs`, `GET /openapi.json` | Интерактивный и машинный контракты |
| `GET /ui/` | Интерфейс сайта |

Пример тела `POST /recommendations` — можно вставить в Swagger:

```json
{
  "city": "Алматы",
  "event_date": "2026-10-07",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "duration_hours": 4.5,
  "language": "казахский"
}
```

`duration_hours` и `language` можно пропустить или передать как `null`. Бюджет — целое число от 1 до 1 000 000 000 ₸; длительность — больше нуля и не больше 168 часов. Дата должна входить в окно календаря. Это технические границы текущего демо.

Ответ содержит `outcome`, `cards`, `message` и `stats`. Все три бизнес-исхода возвращаются с HTTP 200:

| `outcome` | Что видит пользователь |
|---|---|
| `matches` | От одной до трёх карточек и пояснение результата |
| `category_absent` | В выбранном городе нет этой категории |
| `no_match` | Категория есть, но никто не проходит условия; указаны причины |

Некорректный ввод — HTTP 422; повреждённый JSON — 400; слишком большое тело — 413. Полные ограничения, остальные ошибки и интеграционные примеры — в [документации backend](recommendation-logic/README.md) и [HANDOFF.md](recommendation-logic/HANDOFF.md).

## 7. Установка и запуск

Нужны **Git и Python 3.10+**; проверено на Windows с Python 3.13.12. **Node.js 22+** нужен только для JavaScript-тестов. Для обычного запуска не нужны API-ключи, база данных, npm или сборка frontend.

Репозиторий приватный: для клонирования требуется доступ к репозиторию команды.

```bash
git clone https://github.com/BAITC-Hacks/hack-22efa0ed-codexflow.git
cd hack-22efa0ed-codexflow
```

Если репозиторий уже скачан, откройте его корневую папку и переходите к командам ниже.

### Windows PowerShell

```powershell
cd recommendation-logic
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

### Альтернатива для macOS и Linux

```bash
cd recommendation-logic
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

| Адрес после запуска | Что откроется |
|---|---|
| [127.0.0.1:8000/ui/](http://127.0.0.1:8000/ui/) | Рабочий сайт с настоящим подбором по каталогу |
| [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) | Swagger — интерактивная документация API |
| [127.0.0.1:8000/health](http://127.0.0.1:8000/health) | Состояние сервера; ожидается `profiles_loaded: 66` |

Один процесс обслуживает и сайт, и API. Не открывайте `frontend/index.html` двойным щелчком: нужен HTTP-сервер. Остановка — `Ctrl+C`. Если порт занят, замените `8000`, например, на `8013` и откройте `/ui/` на новом порту: сайт использует тот же origin для API.

Адрес `localhost` доступен на вашем компьютере, это не публичная ссылка. Push в GitHub сохраняет код, но не запускает сервер для других пользователей.

## 8. Как проверить решение

### Сценарии для жюри

Откройте `/ui/` **без `?demo=1`**. В форме есть быстрые примеры «Ведущий», «Флорист» и «Низкий бюджет»; затем нажмите «Подобрать подрядчиков».

| Сценарий | Условия | Ожидаемый результат |
|---|---|---|
| Плотная категория | Алматы · 07.10.2026 · свадьба · Ведущий · 1 000 000 ₸ · казахский | Кики, Эмилия, Сон Гоку — три карточки из четырёх подходящих |
| Проверка занятости | В первом запросе изменить только дату на 03.10.2026 | Пустая выдача; четыре иначе подходящих профиля заняты |
| Редкая категория | Алматы · 04.10.2026 · свадьба · Флорист · 250 000 ₸ · русский | Тони Тони Чоппер и Тихиро Огино; объяснение, почему их меньше трёх |
| Недостаточный бюджет | В запросе флористов изменить бюджет на 100 000 ₸ | Карточек нет; стартовые цены свободных кандидатов выше бюджета |
| Нет категории в городе | Зарубежье · 04.10.2026 · свадьба · Флорист · 250 000 ₸ | Отдельный исход: в городе нет этой категории |
| Площадка с несколькими категориями | Алматы · 08.10.2026 · свадьба · Банкетный зал · 3 500 000 ₸; язык и длительность не заданы | Хината Хьюга, Иноскэ Хашибира, Шинобу Кочо; все категории и метки города/цены сохранены |

Повторите первый запрос и сравните порядок. У флористов покажите различие объяснений: объём выполненных заказов у одного и работа с цветовой палитрой у другого. Синтетические профили и ориентировочные цены отмечены отдельно.

Режим `/ui/?demo=1` показывает **сохранённые примеры** для просмотра интерфейса. Он не доказывает работу живого API. Ошибка сети в обычном режиме не подменяется демонстрационными ответами.

Подробнее: [сценарии демонстрации](docs/demo-cases.md), [ручной чек-лист](docs/test-cases.md), [машиночитаемые кейсы](recommendation-logic/examples/demo-cases.json).

### Автоматические проверки

Команды ниже выполняются из `recommendation-logic/`. Используйте Python из созданного окружения: в Windows — `.\.venv\Scripts\python.exe`, в macOS/Linux — `.venv/bin/python`.

```powershell
# Backend, API, безопасность и весь календарь
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# Клиентские контракты и компоненты интерфейса
node --test qa/frontend-integration.test.mjs

# Отдельные тесты помощника
.\.venv\Scripts\python.exe -m unittest discover -s ../contractor_assistant -t .. -p test_chat.py -v

# Живой локальный сервер — запускать в другом терминале
.\.venv\Scripts\python.exe qa/demo_check.py --base-url http://127.0.0.1:8000

# Нагрузочный тест сам запускает отдельный локальный сервер
.\.venv\Scripts\python.exe qa/stress_check.py --output qa-results.json
```

Проверяемый состав: **105 тестов backend + 12 тестов frontend + 6 тестов помощника**. Живой проверочный скрипт содержит **7 кейсов**, включая площадку с несколькими категориями, и повторный запрос для проверки порядка.

Последний полный нагрузочный прогон от 23.09.2026: **10 000 запросов к движку без расхождений с эталоном**, **2 000 HTTP-запросов без ошибок**, максимальное время **6,349 секунды** при параллелизме 64. Отдельный приёмочный тест перебирает **11 200 календарных запросов**, проверяет порядок, ограничения, исходные цитаты и отсутствие одинаковых объяснений после удаления имён.

Эти цифры относятся к локальному окружению, не являются гарантией хостинга или отсутствия любых ошибок. Точный состав проверок и ограничения — в [отчёте приёмки](docs/acceptance-report.md), сценарий нагрузки — в [qa/README.md](recommendation-logic/qa/README.md).

## 9. Данные и интеграции

Источник подбора — [`recommendation-logic/data/providers.csv`](recommendation-logic/data/providers.csv): **66 анонимизированных профилей**, из них **13 синтетических**. Каталог охватывает Алматы, Астану и «Зарубежье»; календарь — **23.09.2026–31.12.2026**, всего 100 дней.

Ведущих — 15, фотографов — 12, банкетных залов — 8; в ряде редких категорий по 3 профиля. Категории пересекаются: один подрядчик может относиться к нескольким.

| Поле | Значение |
|---|---|
| `price_from_kzt` | Стартовая цена за мероприятие, не окончательная смета |
| `busy_dates` | Даты занятости; применяются и к людям, и к площадкам |
| `max_hours` | Максимум часов на площадке либо `null` |
| `synthetic` | Синтетический профиль |
| `city_imputed` | Город проставлен при подготовке датасета |
| `price_imputed` | Цена проставлена при подготовке датасета |

Флаги независимы. Интерфейс показывает происхождение данных; наличие свободной даты в датасете не является подтверждением бронирования. Просматриваемый каталог использует локальный snapshot `frontend/catalog-data.js`; тест сверяет все его поля с серверным CSV. При изменении каталога нужно обновить оба представления.

### Внешние сервисы и интеграции

- **Для основного сценария внешних API нет:** подбор работает по локальному CSV; frontend и backend обслуживаются одним сервером.
- **OpenAI Responses API — опциональная интеграция.** В репозитории задана модель по умолчанию `gpt-4o-mini`, которую можно изменить через `OPENAI_MODEL`. Подключение описано в [AI.md](recommendation-logic/AI.md); API-ключ нельзя публиковать или помещать во frontend.
- **NVIDIA API в текущем коде не интегрирован.** Наличие хакатонных кредитов не означает использование сервиса в приложении.
- **GitHub** используется для командного репозитория, не как сервер приложения. Шрифты и каталог загружаются локально; аналитика или отдельная БД для подбора не подключены.

## 10. Ограничения

- За пределами календаря доступность неизвестна; такие даты не принимаются.
- Помощник распознаёт короткие русскоязычные запросы и уточнения, но не гарантирует понимание произвольной речи. Перед подбором нужно проверить распознанные поля; ручная форма остаётся доступной.
- Каталог учебный и анонимизированный. Сервис не проверяет достоверность заявлений самого подрядчика.
- Ключи хранятся только на сервере. `.env` исключён из Git; обычный запуск не загружает его автоматически.
- Есть валидация типов, чисел и Unicode, лимит тела 16 КиБ, ограничение времени получения тела и безопасное отображение текста. Это не полный аудит инфраструктуры.
- Перед публичным размещением нужны HTTPS, ограничения запросов, контроль доступа к платному ИИ и проверка зависимостей. Подробности — [SECURITY.md](recommendation-logic/SECURITY.md).
- Зависимости заданы диапазонами версий, полного lock-файла нет. Живой LLM, публичный хостинг и чистая установка на другой ОС пока не подтверждены тестированием.

## 11. Развёрнутая версия

**Подтверждённой публичной deployed-версии в репозитории пока нет.** Для проверки используйте локальный запуск по разделу 7 и откройте [http://127.0.0.1:8000/ui/](http://127.0.0.1:8000/ui/).

Этот адрес работает только на компьютере с запущенным сервером. Репозиторий GitHub — исходный код, а не размещённый сайт. После отдельного развёртывания этот раздел можно дополнить проверенной публичной ссылкой.
