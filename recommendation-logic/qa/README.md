# Стресс-проверки и воспроизведение слабых мест

Из `recommendation-logic/`:

```powershell
python qa/stress_check.py --output qa-results.json
python -m unittest discover -s qa -p test_known_weaknesses.py -v
python -m unittest discover -s tests -v
```

Первый скрипт выполняет 10 000 проверок движка с независимым эталоном фильтрации,
12 граничных случаев, масштабирование каталога до 6600 синтетических копий,
2000 HTTP-запросов (500 на каждый уровень параллелизма: 1/8/32/64) и симуляцию ИИ.
Он запускает отдельный однопроцессный сервер только на loopback и останавливает
только собственный процесс. Рабочий сервер и каталог не изменяются. Реальных
вызовов OpenAI нет: ключ тестовый, транспорт полностью подменён, отдельный сервер
запущен с выключенным ИИ. Сценарий ограничен по числу запросов, это не бесконечная нагрузка.

Второй запуск — намеренно красные воспроизведения пяти обнаруженных слабых мест.
Они не замаскированы как expectedFailure и не входят в обычную папку `tests/`:

1. JSON-число `1e309` в duration_hours вызывает HTTP 500 вместо ошибки клиента.
2. Lone surrogate в городе вызывает HTTP 500 при кодировании ответа.
3. Город из 100 000 символов принимается и отражается в ответе.
4. Эквивалентные написания Алматы вызывают четыре обращения к модели вместо одного.
5. Горячий AI-кэш ждёт общий lock и может отдать timeout fallback.

Дополнительный нагрузочный сценарий показывает последовательную обработку разных
AI-запросов: при 32 одновременных и mock-задержке 250 мс часть запросов достигает
таймаута 6 секунд. Это деградация ИИ, не неверная подборка: fallback сохраняется.

В первом прогоне: 55 обычных тестов зелёные, 5 новых воспроизведений красные.
Исправления в production-код в рамках диагностики не вносились. После исправлений
красные проверки должны стать зелёными; их следует перенести в основной regression suite.

Метрики HTTP включают клиент, ОС, сокеты и сервер на одном компьютере; это не
чистое измерение backend и не прогноз мощности хостинга. Генератор не охватывает
все возможные входные значения. Семантическое качество настоящего ИИ не проверено.

Первый приоритет исправлений: безопасные ошибки ввода (числа/Unicode), границы
длины полей и размера тела, затем ключ кэша и параллелизм ИИ с ограничением нагрузки.
