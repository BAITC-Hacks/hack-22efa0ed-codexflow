# Стресс-проверки и регрессии безопасности

Из `recommendation-logic/`:

```powershell
python -m unittest discover -s tests -v
python -m unittest discover -s qa -p test_known_weaknesses.py -v
python qa/stress_check.py --output qa-results.json
```

Обычный набор содержит 105 проверок, включая проход 11 200 календарных запросов и пять ранее падавших воспроизведений,
собираемых через tests/test_security.py. Все пять исправлены: неограниченные числа,
повреждённый Unicode, слишком длинный ввод, эквивалентные ключи кэша и блокировка горячего кэша.

Нагрузочный сценарий: 10 000 запросов к движку с независимым эталоном, 12 граничных
случаев, каталог до 6600 синтетических копий в памяти, 2000 HTTP-запросов
(по 500 при параллелизме 1/8/32/64) и симуляция ИИ. Скрипт запускает отдельный
однопроцессный loopback-сервер и завершает только свой процесс. Реальных вызовов
модели нет, её транспорт заменён тестовым; исходный каталог не меняется.

После исправлений: 10 000 запросов без расхождений, 2000 HTTP без ошибок обычного
подбора. Все некорректные входы из набора дают 4xx, не 500. При 32 разных AI-запросах
и mock-задержке 250 мс теперь 32 успеха, 0 таймаутов, максимум около 2,11 с.
В прежнем прогоне были 22 успеха и 10 timeout fallback с максимумом около 6 с.
Одинаковое написание города с разным регистром/пробелами использует один AI-вызов,
а горячий кэш не ждёт lock.

HTTP p95 при 64 одновременных запросах в финальном прогоне 23.09.2026: около 2,745 с, максимум 6,349 с.
Эти цифры включают клиент, ОС и сервер на одном компьютере и не являются
гарантией скорости на хостинге. Генератор ограничен, это не многодневный soak-тест.
Качество и скорость настоящей модели пока не проверены.
Оставшиеся требования публичного размещения описаны в ../SECURITY.md.
