# Recommendation logic

Движок подбора и локальный FastAPI-сервер для 66 event-подрядчиков.
Внешние API, ключи и AI-модели для запуска не нужны. Python 3.10+; проверено на 3.13.
Опциональный ИИ-выбор фактов для объяснений: [подключение, контракт и ограничения](AI.md).
По умолчанию отключён; основной подбор работает как раньше.
Для коллеги по интерфейсу: [HANDOFF.md](HANDOFF.md) — контракт, ошибки и порядок демо.
Готовые запросы: [examples/demo-cases.json](examples/demo-cases.json).

## Запуск

Все команды ниже выполняются из `recommendation-logic/`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m uvicorn src.api:app --reload
```

Если зависимости уже установлены, можно использовать `python` вместо пути к `.venv`.
Swagger: http://127.0.0.1:8000/docs. Остановка сервера: Ctrl+C.
Сайт: http://127.0.0.1:8000/ui/ — тот же сервер отдаёт `../frontend/` и API.
После переноса из корня репозитория старый сервер следует остановить и запустить заново.

## Устройство

- `src/recommendation.py`: чтение CSV, общая проверка и нормализация ввода, фильтры, порядок и объяснения.
- `src/api.py`: HTTP, модели запросов и ответов, Swagger, CORS.
- `data/providers.csv`: исходный каталог без изменений.
- `tests/`: модульные, каталожные, API- и регрессионные проверки.

Порядок: город + категория → все обязательные условия → сортировка по цене «от»,
затем по `id` → первые три карточки. Одинаковые параметры дают одинаковый порядок.
Это прозрачная сортировка по цене, не оценка качества подрядчика и не семантический AI-рейтинг.
Объяснения используют факты каталога и полные короткие фразы из описания.
Первое предложение выделяет особенность профиля: конкретный опыт, языки, стиль,
оснащение или объём работы; рекламные превосходные степени отсекаются эвристикой.
Фраза выбирается детерминированно с учётом формата события, без дописывания фактов.
Второе предложение связывает дату, формат, язык и длительность с запросом,
показывает разницу между стартовой ценой и бюджетом и напоминает уточнить итоговую стоимость.
Общая выдача объясняет сортировку по цене, а не по качеству, и занятость иначе
подходящих профилей. Если профили неразличимы по данным, это отмечается честно.
Длинные фразы не обрезаются: вместо них используются структурированные данные профиля.
Различие текстов проверяется на демо-запросах, но содержательность объяснений также требует ручного просмотра.

## Контракт для интерфейса

- `GET /health`: `status`, `profiles_loaded`.
- `GET /filters`: `cities`, `categories`, `event_formats`, `languages`, `event_date_range`.
- `POST /recommendations`: JSON ниже. Ответы и ошибки описаны в `/docs` и `/openapi.json`.

```json
{
  "city": "Алматы",
  "event_date": "2026-10-07",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "duration_hours": 4.5,
  "language": "казахский"
}
```

Правила общие для API и прямого вызова движка:

- Город, формат, категория и язык сопоставляются без учёта регистра и повторных пробелов.
  `Свадьба` и `свадьба` дают одинаковый результат; в ответе сохраняется написание из каталога.
- Дата: строго строка `YYYY-MM-DD`, с 23.09.2026 по 31.12.2026 включительно.
  Это окно покрытия календаря, а не диапазон фактически занятых дней. За его пределами доступность неизвестна.
- Бюджет: положительное целое JSON-число. Строки, дробные числа и `true`/`false` не принимаются.
- Технические границы демо: текстовые поля до 128 символов, бюджет до 1 млрд ₸,
  длительность до 168 часов; эти верхние границы заданы в движке и OpenAPI.
  Некорректный Unicode, скрытые управляющие символы и непредставимые числа отклоняются.
- Длительность: положительное конечное число часов, допускается `4.5`. Можно не передавать или указать `null`.
- Язык: непустая строка, можно не передавать или указать `null`. Пустая строка и пробелы — ошибка.
- Неизвестные поля (например, `languag`) — ошибка HTTP 422, чтобы не терять фильтры незаметно.
- Неизвестная непустая категория/город даёт `category_absent`; неподдерживаемые формат/язык при наличии категории дают `no_match`.

Каждый успешный ответ HTTP 200 содержит:

```text
outcome: matches | category_absent | no_match
cards: массив из 0–3 карточек
message: объяснение результата для пользователя
stats:
  catalog_candidates: число профилей выбранных города и категории
  eligible: число профилей, прошедших все условия до ограничения до трёх
  rejected: объект со счётчиками причин (пустой {}, если причин нет)
```

Карточка: `id`, `name`, `categories` (массив), `city`, `price_from_kzt`,
`synthetic`, `city_imputed`, `price_imputed`, `explanation`.
Интерфейс должен показывать цену как «от» и метки происхождения данных.
`max_hours = null` в каталоге означает, что работа не привязана к присутствию:
фильтр длительности такой профиль не исключает; это не обещание неограниченной работы на площадке.

Причины в `rejected`: `busy`, `budget`, `format`, `duration`, `language`.
Один профиль может нарушать несколько условий, поэтому сумму счётчиков нельзя считать числом людей
или последовательной воронкой. Отсутствующий ключ причины означает ноль.

При пустой выдаче сообщение отдельно называет профили, не прошедшие ровно одно условие:
например, четыре подходят по всем остальным параметрам, но заняты, а ещё один подходит,
но превышает бюджет. Минимальная цена в таком сообщении относится только к свободным
профилям, прошедшим остальные условия. Если каждому мешают несколько условий,
возвращается общее объяснение с предупреждением о пересекающихся причинах.
Полная статистика `rejected` при этом всегда описывает весь выбранный город и категорию.

Ошибки ввода возвращают HTTP 422 с массивом `detail`; поле указано в `loc`, пояснение — в `msg`.
Сырые `input` и `ctx` не возвращаются. Некорректный JSON и повторяющиеся ключи дают 400,
тело больше 16 КиБ — 413, неверный Content-Type/сжатое тело — 415,
передача тела дольше 3 секунд — 408. Ограничение проверяется и для chunked-передачи.
Пустая выдача — обычный HTTP 200 с `no_match` или `category_absent`, не техническая ошибка.

CORS разрешает `http://localhost:5173` и `http://127.0.0.1:5173`.
При другом порте интерфейса нужно согласованно изменить список в `src/api.py`.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Проверка уже запущенного локального API без расходов на ИИ:

```powershell
python qa/demo_check.py --base-url http://127.0.0.1:8000
```

Регрессионные тесты воспроизводят ошибки границ календаря, сокращённой даты,
пробелов, булевых бюджетов, дробных часов, неизвестных полей и отсутствующих полей ответа.
Они сравнивают прямой вызов и HTTP для 66 запросов на основе каталога, а также
проверяют сценарии команды из `../docs/demo-cases.md`.
Это покрытие конкретных сценариев, а не доказательство отсутствия всех возможных ошибок.
Регрессии безопасности входят в обычный запуск тестов. Подробности и границы
защиты: [SECURITY.md](SECURITY.md); нагрузочный сценарий: [qa/README.md](qa/README.md).

В текущем окружении Starlette выводит предупреждение об устаревающем тестовом адаптере `httpx`;
оно не мешает тестам. Зависимости пока заданы диапазонами версий, не полным lock-файлом.
