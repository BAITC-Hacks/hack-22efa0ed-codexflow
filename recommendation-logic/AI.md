# ИИ для индивидуальных объяснений

## Что реализовано

ИИ не является чат-ботом и не выбирает состав выдачи. Движок сначала проверяет
город, категорию, дату, бюджет, формат, язык и длительность, затем сортирует по
цене и ID. Только для уже выбранных карточек модель выбирает наиболее релевантную
фразу из описания. Она видит параметры заказа, карточки и до 12 коротких фраз
на каждого из максимум трёх подрядчиков, а не весь каталог или календарь.

OpenAI Responses API возвращает строгий JSON: ID подрядчика → индекс фразы.
Сервер проверяет все ID и индексы; собственный текст модели никогда не отображается.
Объяснение собирается из структурированных фактов и точной цитаты исходного профиля.
Это ограничивает выдумки модели, но не проверяет достоверность самого датасета.
Качество выбора фразы нужно оценить на реальной модели: прохождение технических
тестов само по себе не доказывает улучшение объяснений.

Формат подключения проверен по [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Модель по умолчанию — `gpt-4o-mini`, можно сменить через `OPENAI_MODEL` на модель
с поддержкой Responses API и строгого JSON Schema. Доступность в аккаунте не проверена.

## Включение локально

По умолчанию функция выключена, внешних вызовов нет. Из `recommendation-logic/`:

1. Скопируйте `.env.example` в `.env` и откройте `.env` в VS Code.
2. Впишите в локальный файл `OPENAI_API_KEY` и `AI_EXPLANATIONS_ENABLED=true`.
3. Запустите сервер, явно загрузив настройки:

```powershell
python -m uvicorn src.api:app --reload --env-file .env
```

`uvicorn[standard]` уже входит в requirements. Не присылайте ключ в чат,
не вставляйте во frontend и не коммитьте `.env`. Файл игнорируется Git.
Промокод на кредиты не является API-ключом. После смены настроек перезапустите сервер.
Обычный запуск без `--env-file` не читает `.env` автоматически.

## Контракт для участника, который делает интерфейс

Тело запроса и JSON ответа **не изменились**. Включение на один запрос:

```text
POST /recommendations?ai_explanations=true
```

Без параметра работает прежний подбор. Клиент по-прежнему отображает
`cards[].explanation`. Новых обязательных полей нет. UI в рамках этой задачи не менялся.
В Swagger появится необязательный параметр `ai_explanations`.

Честный индикатор ИИ можно построить по заголовкам ответа (они доступны через CORS):

| X-Explanation-Source | Значение |
| --- | --- |
| `rules` | Обычные объяснения: не запрошен ИИ, отключён, пустая выдача или нет подходящих фраз |
| `ai` | Модель выбрала фразы; индексы проверены, объяснения собраны сервером |
| `ai_cache` | Проверенный результат из памяти текущего процесса |
| `fallback` | ИИ запрошен, но недоступен/ответ некорректен; показана обычная выдача |

`X-AI-Reason` содержит безопасный код: `not_requested`, `disabled`, `empty_result`,
`no_evidence`, `missing_key`, `timeout`, `network`, `upstream_http`,
`invalid_response`, `call_limit` или `ok`. Ошибки/ключи внешнего провайдера клиенту
не раскрываются. Не показывайте пользователю «ИИ включён» только по состоянию переключателя.

## Надёжность и ограничения

- Пустые результаты объясняются правилами без расходов на модель.
- Один вызов для всей подборки; автоматических повторов нет.
- Общий таймаут ИИ — 6 секунд, включая очередь. После него используется fallback.
- Кэш ограничен 128 результатами и учитывает запрос, модель и исходные карточки/фразы.
- Одинаковые одновременные запросы используют один вызов. Вызовы сериализованы.
- Лимит — 30 попыток на процесс, включая ошибки; кэш работает и после исчерпания лимита.
- Это не денежный лимит аккаунта: рестарт/другой worker обнуляет локальный счётчик.
  Перед публичным запуском нужны ограничение расходов у провайдера, rate limit и
  контроль доступа. Сейчас модуль рассчитан на локальное демо, не публичную нагрузку.
- Порядок карточек всегда детерминирован; выбранная фраза после рестарта/очистки кэша
  может измениться. Прямой вызов движка остаётся полностью без ИИ.
- Короткая цитата может совпасть с обычным объяснением; ИИ не обязан менять текст.
- `store=false` отключает сохранение Response для дальнейшего получения через API;
  это не обещание полного отсутствия хранения данных у провайдера.
- Описания считаются данными, не инструкциями. Модель может выбрать неудачную
  исходную фразу, но не может вывести новый текст, сменить цену или выдать занятого.

## Проверки и честный статус

```powershell
python -m unittest discover -s tests -p test_ai_explanations.py -v
python -m unittest discover -s tests -v
```

Тесты используют контролируемый HTTP-транспорт, не настоящий ключ и не платные
запросы. Проверены успешный ответ, кэш, сохранение полей и порядка, ошибки 401/429/500,
сеть, отказ модели, некорректные ID/индексы, таймаут, лимит попыток и отключённый режим.

**На момент реализации живой вызов не выполнен: в окружении отсутствовал API-ключ.**
После подключения ключа в `/docs` запустите демо ведущих с `ai_explanations=true`,
проверьте заголовок `ai`, затем `ai_cache` при повторе. Сравните с запросом без ИИ:
карточки, порядок, цены и статистика должны совпадать. Оцените, действительно ли
выбранные цитаты лучше объясняют различия, и укладывается ли запрос в 10 секунд.
Пока такая проверка не выполнена, нельзя заявлять, что качество реального ИИ подтверждено.
