# Передача backend участнику, который делает интерфейс

Это инструкция по интеграции. Каталог и JSON-контракт
успешного подбора сохранены. Все примеры запускаются без ИИ и без ключей.

## 1. Запуск

Из корня репозитория:

```powershell
cd recommendation-logic
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

Готовый сайт: http://127.0.0.1:8000/ui/ — сайт и API обслуживаются одним сервером.
API: http://127.0.0.1:8000; Swagger: http://127.0.0.1:8000/docs.
Frontend с origin http://localhost:5173 или http://127.0.0.1:5173 разрешён CORS.
Если 8000 занят, выберите другой порт и откройте /ui/ на нём: URL API определится
автоматически по адресу страницы. Для отдельного frontend на 5173 API ожидается
на 8000 с тем же hostname. Не останавливайте чужой процесс.
localhost на другом компьютере означает именно тот другой компьютер, не сервер команды.

Обычная страница работает с настоящим каталогом. Только явный параметр ?demo=1
включает сохранённые демонстрационные ответы; ошибка сети не подменяется ими.
Календарь фиксирован условиями хакатона, а не текущими часами компьютера.
Помощник «Опишу своё событие» использует POST /assistant/chat для разбора русских
описаний по правилам и уточнения недостающих условий. После подтверждения заполняет
основную форму и вызывает тот же POST /recommendations. Плавающий чат не монтируется.
По умолчанию нейросеть не вызывается; ключи для работы не нужны.

Проверки интеграции из recommendation-logic (Node.js 22+ для JS-тестов):

```powershell
python -m unittest discover -s tests -v
node --test qa/frontend-integration.test.mjs
python qa/demo_check.py --base-url http://127.0.0.1:8000
```

Последняя команда требует работающий сервер. Первые две — нет.

## 2. Точки подключения

| Запрос | Назначение |
|---|---|
| GET /health | Ожидается status=ok и profiles_loaded=66 |
| GET /filters | Списки городов, категорий, форматов, языков и границы календаря |
| POST /recommendations | Основной подбор, Content-Type: application/json |
| GET /openapi.json | Машинная спецификация полей и ограничений |

Пример тела POST (без вложенного order):

```json
{
  "city": "Алматы",
  "event_date": "2026-10-07",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "duration_hours": null,
  "language": "казахский"
}
```

duration_hours/language необязательны: пропустить или передать null, не пустую строку.
Период календаря 23.09.2026–31.12.2026; бюджет — целое 1..1 млрд ₸;
длительность >0 и <=168 часов; текстовые поля <=128 символов. Строки с числами
вместо JSON-чисел, неизвестные поля и boolean вместо бюджета не принимаются.

## 3. Отображение без потери главного

HTTP 200 содержит outcome, cards, message, stats. Возможны три исхода:

- matches: от 1 до 3 карточек; показывать message даже при успешном подборе.
- no_match: карточек нет; показывать message, объясняющий ограничения.
- category_absent: карточек нет; отдельно показывать отсутствие категории в городе.

В карточке показывать name, categories, city, цену price_from_kzt с подписью «от»
и **полный explanation**, не заменяя его общей фразой. Это главный критерий задания.
Текст содержит отличительную цитату и соответствие условиям запроса, всего два предложения.
Не выдавать цену «от» за окончательную, а порядок — за рейтинг качества.

Метки synthetic, city_imputed и price_imputed не скрывать. Текст вставлять как
обычный текст (например textContent), не как HTML: данные каталога не являются разметкой.
stats.rejected содержит пересекающиеся причины; сумма счётчиков не равна числу людей.

## 4. Ошибки и состояния

| HTTP | Ожидаемая обработка |
|---|---|
| 400 | Некорректный JSON/числа/повторяющиеся ключи; общий текст ошибки |
| 408 | Тело запроса поступало слишком долго; предложить повторить |
| 413 | Тело больше 16 КиБ; исправить запрос, не повторять автоматически |
| 415 | Нужен несжатый application/json |
| 422 | detail — массив loc/msg/type; подсветить соответствующее поле |
| Сеть/5xx | Состояние недоступности, ручной повтор; не подставлять mock-успех |

Для 422 поле обычно в detail[i].loc[1]; input/ctx больше не возвращаются.
Для остальных ошибок detail может быть строкой: не считать его всегда массивом.
При отправке блокировать повторную кнопку, после ответа разблокировать; устаревший
ответ предыдущего запроса не должен заменять более новый результат.

## 5. Готовые примеры и проверка одной командой

Файл [examples/demo-cases.json](examples/demo-cases.json) содержит ровно те JSON,
которые нужно отправлять (поле request), и ожидаемые результаты для QA.
Метаданные expected_* из примера НЕ отправляются на сервер.

В другом терминале из recommendation-logic:

```powershell
python qa/demo_check.py --base-url http://127.0.0.1:8000
```

Скрипт проверяет health, календарь, семь сценариев, карточки/порядок, наличие
объяснений и повторный запрос. Код завершения 0 — всё прошло, 1 — ошибка.
Он предназначен только для явно указанного локального HTTP-сервера, не запускает
сервер сам и никогда не включает ИИ; внешние proxy и redirect не используются.

Порядок показа жюри:

1. Ведущие, 7 октября: Кики, Эмилия, Сон Гоку; из четырёх подходящих показаны три.
2. Повторить запрос: порядок тот же; обсудить отличия без имён.
3. Та же свадьба 3 октября: четыре иначе подходящих профиля заняты.
4. Флористы, 250 000 ₸: два результата, видны разные особенности и метки данных.
5. Флористы, 100 000 ₸: объяснение минимальной подходящей стартовой цены 200 000 ₸.
6. Банкетные залы, 8 октября: у профилей показаны все категории и раздельные метки city_imputed/price_imputed.
7. Зарубежье + Флорист: отдельный исход category_absent.

Нулевой бюджет — дополнительная QA-проверка поля, а не обязательный сценарий защиты.

## 6. ИИ — отдельная необязательная проверка

По умолчанию ИИ выключен. Настройки и локальный ключ описаны в [AI.md](AI.md).
Для запроса с ИИ используется /recommendations?ai_explanations=true; схема JSON прежняя.
Показывать факт использования ИИ только по X-Explanation-Source (ai/ai_cache),
не по переключателю. rules/fallback — обычные объяснения; X-AI-Reason — безопасная причина.
Ключ нельзя помещать в JavaScript, репозиторий или пересылать в чат.
Реальная модель ещё не проверена, и качество её выбора не следует обещать жюри заранее.

## 7. Короткое объяснение пайплайна для защиты

«Сначала проверяем город, категорию, занятость и ограничения заказа. Оставшихся
сортируем по стартовой цене, при равенстве — по постоянному ID. Показываем до трёх
вариантов, выделяем факты их описаний и объясняем соответствие заказу. Опциональная
модель выбирает только исходную фразу; она не меняет цены, доступность и порядок».

Перед публичным запуском остаются требования из [SECURITY.md](SECURITY.md): HTTPS,
ограничение запросов и доступа к платному AI, общие квоты, проверка зависимостей.
