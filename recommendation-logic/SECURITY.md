# Границы защиты backend

## Реализовано и проверено

- Только JSON для POST /recommendations; повторяющиеся ключи и неограниченные числа
  отклоняются до обработки запроса. Неверная кодировка и слишком глубокий JSON — ошибка клиента.
- Размер тела максимум 16 КиБ, измеряется по принятым байтам, а не только заголовку;
  дублирующийся/некорректный Content-Length отклоняется, сжатые тела не поддерживаются.
- На получение тела отведено 3 секунды; слишком медленный клиент получает 408.
- Строки до 128 символов; Unicode surrogates, невидимые format/control символы запрещены.
  Обычные пробелы и окружающие табуляции/переносы нормализуются прежним способом.
- Бюджет 1..1 000 000 000 ₸, длительность >0 и <=168 часов. Это технические пределы
  текущего демо, не универсальные бизнес-правила для всех мероприятий.
- API и прямой вызов движка используют одни валидаторы.
- Ошибки 422 не включают сырые input/ctx: только bounded loc/msg/type, максимум 16 ошибок.
- Заголовки nosniff, no-referrer; ответы рекомендаций имеют Cache-Control: no-store.
- CORS разрешает только указанные локальные origins, включая ответы с ошибками.
- .env и .git не раздаются через static mount; ключ остаётся только на backend.
- ИИ выбирает индекс исходной фразы. Его произвольный текст/цены/ID в карточки не попадают.
- AI: 4 внешних вызова одновременно, 32 незавершённые задачи, 30 попыток на процесс,
  6 секунд общего таймаута, 128 кэшированных результатов. Перегрузка → обычные объяснения.
- Одинаковые запросы разделяют одну задачу; отмена одного ожидающего не отменяет других.

Проверки: `python -m unittest discover -s tests -v`; нагрузка описана в qa/README.md.
Факты в объяснениях и качество текстов проверяются отдельно, чтобы безопасность
не ухудшала подбор и не скрывала причину пустого результата.

## Что это НЕ гарантирует

Это усиление приложения, не аудит всей инфраструктуры и не защита от любого DDoS.
ASGI получает данные после сетевого сервера; лимит приложения не заменяет ограничения
буферов, соединений и таймаутов на прокси. JSON не исполняется как код; отсутствие БД
в текущем движке не означает, что будущие интеграции автоматически безопасны.

Перед публичным размещением обязательны:

1. HTTPS, лимиты размера/скорости и количества соединений на reverse proxy/платформе.
2. Аутентификация или иные меры против злоупотреблений платным AI, per-client rate limit.
   CORS НЕ является аутентификацией и не блокирует запросы вне браузера.
3. Общие квоты между workers/репликами и лимиты расходов в аккаунте провайдера.
   Сейчас счётчик/кэш локальны процессу; рестарт обнуляет их.
4. Проверка версий и уязвимостей зависимостей, фиксация воспроизводимого окружения.
   Полный dependency audit в этой работе не выполнялся.
5. Санитарные логи без ключей и тел пользовательских запросов, мониторинг 4xx/5xx/429.
6. Настройка допустимых origin/host для домена размещения, без wildcard по умолчанию.

Живой OpenAI API, публичный хостинг, TLS и внешний периметр этим прогоном не проверялись.
